# SNES_MiSTer Clock Analysis

Top-to-bottom trace of every clock domain, clock enable, and derived timing signal in the design.

---

## 1. PLL — Clock Generation (`SNES.sv:223`)

The Altera fractional-N PLL takes the board's 50 MHz input and produces three output clocks:

```
CLK_50M (50 MHz, board oscillator)
  └─ pll
       ├─ outclk_0 → clk_mem    (85.90908 MHz)  — SDRAM / DDR interface
       ├─ outclk_1 → CLK_VIDEO  (42.95454 MHz)  — video output to framework
       └─ outclk_2 → clk_sys    (21.47727 MHz)  — main system clock (NTSC)
```

These are the NTSC frequencies. For PAL, the PLL is dynamically reconfigured at runtime via `pll_cfg` (address 7, magic constant `2201376898` for PAL vs `2537930535` for NTSC). This shifts all three outputs proportionally:

| Output | NTSC | PAL |
|--------|------|-----|
| `clk_mem` | 85.909 MHz | 85.125 MHz |
| `CLK_VIDEO` | 42.955 MHz | 42.563 MHz |
| `clk_sys` | 21.477 MHz | 21.281 MHz |

The reconfiguration is triggered on `CLK_50M` whenever the `PAL` status bit changes (`SNES.sv:256-286`).

## 2. Top-Level Clock Routing (`SNES.sv`)

### `clk_sys` domain (21.477 MHz)
Nearly everything runs in this domain. The `main` module receives it as both `MCLK` and `ACLK`:

```systemverilog
main main(
    .MCLK(clk_sys),    // master clock
    .ACLK(clk_sys),    // audio clock (same physical clock)
    ...
);
```

Inside `main.v`, these are forwarded to `SNES.vhd` as:
- `MCLK` → CPU, PPU, WRAM, Game Genie, coprocessor map controllers
- `ACLK` → `DSPCLK` input on `SNES.vhd`, used by SMP and DSP

Since `MCLK` and `ACLK` are the same 21.477 MHz clock, the audio subsystem uses `CEGen` to derive the correct audio rate internally (see section 5).

### `clk_mem` domain (85.909 MHz)
Used by:
- SDRAM controller (`sdram.sv:clk`)
- DDR3 interface (`DDRAM_CLK` directly assigned to `clk_mem`)
- Download data synchronizer (`SNES.sv:861`, ROM data latched on `posedge clk_mem`)

### `CLK_VIDEO` domain (42.955 MHz)
Used by:
- Pixel clock enable generation (`ce_pix`)
- Video mixer input
- Aspect ratio / crop calculations
- DOTCLK edge detection for pixel sampling

### `CLK_AUDIO` (24.576 MHz)
External clock from MiSTer framework, used only by the `audio_out` module for I2S serialization. Not generated by the core PLL.

## 3. CPU Clock Enable Generation (`rtl/CPU.vhd:239-343`)

The CPU does **not** use a divided clock. It runs on `MCLK` (21.477 MHz) and generates single-cycle pulse enables that gate all system activity. Two free-running counters produce the timing:

### DMA clock counter
```
DMA_CLK_CNT[2:0]  — always free-running, counts 0→7 (8 MCLK cycles per beat)
DMA_MID_CLOCK = 3  — rising edge point
DMA_LAST_CLOCK = 7 — falling edge point
```

This counter never stops. It provides the base ~2.68 MHz timing grid and also derives fixed-ratio sub-clocks:

```
CLK4_CE_F = (DMA_CLK_CNT[1:0] == "01")  — ~5.37 MHz, used for HBLANK/VBLANK/IRQ edge detection
CLK4_CE_R = (DMA_CLK_CNT[1:0] == "11")  — ~5.37 MHz rising
CLK8_CE_F = (DMA_CLK_CNT[2:0] == "011") — ~2.68 MHz, used for joypad auto-read, HDMA init
```

### CPU clock counter
```
P65_CLK_CNT[3:0]  — counts 0→CPU_LAST_CLOCK, then resets
CPU_MID_CLOCK      — rising edge point (variable)
CPU_LAST_CLOCK     — falling edge point / terminal count (variable)
```

`CPU_LAST_CLOCK` is set dynamically based on the memory region being accessed:

| Condition | CPU_LAST_CLOCK | CPU_MID_CLOCK | Effective CPU rate | SNES speed class |
|-----------|---------------|---------------|-------------------|-----------------|
| Turbo + RAM access | 0x5 (6 cycles) | 0x1 | 3.58 MHz | Turbo |
| Turbo + ROM access | 0x3 (4 cycles) | 0x1 | 5.37 MHz | Turbo |
| DRAM refresh active | 0x7 (8 cycles) | 0x2 | 2.68 MHz | (forced slow) |
| FAST memory | 0x5 (6 cycles) | 0x2 | 3.58 MHz | FastROM |
| SLOW memory | 0x7 (8 cycles) | 0x2 | 2.68 MHz | SlowROM |
| XSLOW (I/O regs) | 0xB (12 cycles) | 0x2 | 1.79 MHz | XSlow |

Memory speed determination (`CPU.vhd:362-392`) maps the 24-bit CPU address to a speed class:

| Address Range | Speed | Description |
|--------------|-------|-------------|
| `$00-3F/$80-BF:$2100-$21FF` | XSLOW | PPU/APU I/O registers |
| `$00-3F/$80-BF:$4000-$41FF` | XSLOW | CPU I/O registers |
| `$00-3F/$80-BF:$4200-$5FFF` | FAST | Internal CPU registers |
| `$00-3F:$8000-$FFFF` | SLOW or SLOWFAST | LoROM area (depends on MEMSEL) |
| `$80-BF:$8000-$FFFF` | SLOWFAST | HiROM area |
| `$40-$7D:any` | SLOW | Expansion |
| `$7E-$7F:any` | SLOW | WRAM |
| `$C0-$FF:any` | SLOWFAST | HiROM high banks |

`SLOWFAST` resolves to FAST or SLOW at runtime based on the `MEMSEL` register bit (`$420D`).

### Clock enable output generation

When the **DMA** has the bus (`DMA_ACTIVEr = 1`) or the system is disabled:
```
INT_CLKR_CE pulses when DMA_CLK_CNT = DMA_MID_CLOCK (3)
INT_CLKF_CE pulses when DMA_CLK_CNT = DMA_LAST_CLOCK (7)
```

When the **CPU** has the bus (`CPU_ACTIVEr = 1`):
```
INT_CLKR_CE pulses when P65_CLK_CNT = CPU_MID_CLOCK
INT_CLKF_CE pulses when P65_CLK_CNT >= CPU_LAST_CLOCK
```

These become the global system clock enables:
```vhdl
SYSCLKF_CE <= INT_CLKF_CE;   -- "falling edge" enable
SYSCLKR_CE <= INT_CLKR_CE;   -- "rising edge" enable
```

`INT_CLK` tracks the virtual system clock level (toggles high on `INT_CLKR_CE`, low on `INT_CLKF_CE`), exposed as `SYSCLK`.

### CPU/DMA bus arbitration

`CPU_ACTIVEr` and `DMA_ACTIVEr` are mutually exclusive. Transitions happen only at counter terminal counts:
- DMA seizes the bus when `DMA_ACTIVE` asserts and `DMA_CLK_CNT` reaches `DMA_LAST_CLOCK`
- CPU regains the bus when `DMA_ACTIVE` deasserts and `P65_CLK_CNT` reaches `CPU_LAST_CLOCK`

### 65C816 core gating (`CPU.vhd:351`)

```vhdl
P65C816 port map(
    CLK  => CLK,                                          -- MCLK
    CE   => (not REFRESHED) and INT_CLKF_CE and DBG_CPU_EN,
    RDY_IN => P65_EN                                       -- not DMA_ACTIVE and ENABLE
);
```

The CPU core advances one micro-step per `INT_CLKF_CE` pulse, but only when not in refresh and DMA is not running.

## 4. PPU Dot Clock Generation (`rtl/PPU.vhd:311-346`)

The PPU runs on `MCLK` and derives its pixel clock from a 3-bit counter:

```vhdl
DOT_CYCLES := "100";  -- default: divide by 4 → 5.369 MHz dot clock

-- Special cases:
-- H_CNT = 323 or 327: DOT_CYCLES := "110" (divide by 6, short dots)
-- V_CNT = 240, non-interlace, odd field, NTSC: DOT_CYCLES := "100"
```

Normal dot clock rate: **21.477 / 4 = 5.369 MHz** (one pixel every 4 MCLK cycles).

At H positions 323 and 327, the dot period stretches to 6 MCLK cycles. This implements the SNES's slightly irregular scanline timing (1364 master cycles per line, with two 6-cycle dots mixed into otherwise 4-cycle dots).

The counter generates two enables per dot period:
```
DOT_CLKF_CE  — pulses at CLK_CNT = 0 (falling edge of dot clock)
DOT_CLKR_CE  — pulses at CLK_CNT = DOT_CYCLES-2 (rising edge of dot clock)
```

`DOT_CLK` itself toggles: low at `CLK_CNT = 1`, high at `CLK_CNT = DOT_CYCLES-1`.

### H/V counters (`PPU.vhd:826-861`)

Advance on `DOT_CLKR_CE`:

| Parameter | NTSC | PAL |
|-----------|------|-----|
| `DOT_NUM` | 340 | 340 |
| `LAST_DOT` | 339 | 339 (340 on specific PAL interlace line) |
| `LINE_NUM` | 262 | 312 |
| `LAST_VIS_LINE` | 224 (no overscan) / 239 (overscan) | same |

### DOTCLK to video output (`SNES.sv:1043-1054`)

The PPU's `DOT_CLK` output is re-sampled in `clk_sys` domain and edge-detected. On each DOTCLK transition, RGB and sync signals are latched:
```systemverilog
always @(posedge clk_sys) begin
    DOTCLK <= DOTCLK_out;
    if(DOTCLK ^ DOTCLK_out) begin  // edge detect
        R <= R_out; G <= G_out; B <= B_out;
        HSYNC <= HSYNC_out; VSYNC <= VSYNC_out;
        HBlank <= ~HBlank_out; VBlank <= ~VBlank_out;
    end
end
```

### CE_PIXEL generation (`SNES.sv:1067-1089`)

In the `CLK_VIDEO` domain (42.955 MHz = 2x `clk_sys`), a 3-bit counter `pcnt` is reset on each DOTCLK rising edge. `ce_pix` fires when the low 2 bits are zero, with an additional gate for high-res mode:
```systemverilog
ce_pix <= !pcnt[1:0] & (frame_hres | ~pcnt[2]);
```
- Normal resolution (256px): `ce_pix` fires every 8 `CLK_VIDEO` cycles → 5.37 MHz pixel rate
- High resolution (512px): `ce_pix` fires every 4 `CLK_VIDEO` cycles → 10.74 MHz pixel rate

## 5. Audio Clock Enable — CEGen + DSP (`rtl/CEGen.vhd`, `rtl/DSP.vhd:236-278`)

### CEGen — fractional clock enable generator

A general-purpose accumulator that produces clock enables at an exact frequency ratio:

```vhdl
-- On each falling_edge(CLK):
CLK_SUM := CLK_SUM + OUT_CLK;
if CLK_SUM >= IN_CLK then
    CLK_SUM := CLK_SUM - IN_CLK;
    CE <= '1';    -- pulse for one clock cycle
end if;
```

This is a first-order bresenham/DDA algorithm. It produces `OUT_CLK / IN_CLK` enables per input clock cycle on average, with ±1 cycle jitter.

### DSP frequency constants (`rtl/DSP_PKG.vhd:8-11`)

```vhdl
constant MCLK_NTSC_FREQ : integer := 21477270;   -- 21.477270 MHz
constant MCLK_PAL_FREQ  : integer := 21281370;   -- 21.281370 MHz
constant ACLK_TYPE_FREQ : integer :=  4096000;   --  4.096000 MHz (type-accurate)
constant ACLK_REAL_FREQ : integer :=  4104960;   --  4.104960 MHz (real hardware)
```

The DSP's `FREQ` input selects between `ACLK_TYPE_FREQ` (default) and `ACLK_REAL_FREQ`. The `PAL` input selects the reference frequency. CEGen then produces `CE` pulses at the target audio rate from whatever `CLK` (= `clk_sys`) is actually running at.

Effective audio clock rate: **~4.096 MHz** (or ~4.105 MHz in "real freq" mode).

### DSP step/substep counter (`DSP.vhd:253-278`)

Each `CE` pulse advances a 2-bit substep counter. Every 4 substeps, a 5-bit step counter advances:

```
CE pulse rate: ~4.096 MHz
Substep rate:  ~4.096 MHz (one substep per CE)
Step rate:     ~1.024 MHz (one step per 4 substeps = 4 CE pulses)
Full cycle:    32 steps × 4 substeps = 128 CE pulses → ~32 kHz sample rate
```

The DSP processes one voice per step (8 voices over 32 steps with interleaved memory operations).

### SMP clock enables (from DSP to SMP)

```vhdl
SMP_EN_F <= ENABLE when SUBSTEP = 3 else '0';  -- fires once per step (at substep 3)
SMP_EN_R <= ENABLE when SUBSTEP = 0 else '0';  -- fires once per step (at substep 0)
SMP_CE   <= CE;                                  -- raw CEGen output
```

The SMP (SPC700 wrapper) receives these and combines them:
```vhdl
SPC700_CE_F <= EN_F and CE;   -- SPC700 executes on this
SPC700_CE_R <= EN_R and CE;
```

Effective SPC700 execution rate: **~1.024 MHz** (one instruction micro-step per `SPC700_CE_F` pulse, which fires once per DSP step).

## 6. SMP Timers (`rtl/SMP.vhd:210-354`)

Three hardware timers run off the SPC700 clock with programmable prescalers:

### Timer step calculation
```vhdl
TM_STEP := ("00001" sll CLK_SPEED) + ("00010" sll TM_SPEED);
```

`CLK_SPEED` and `TM_SPEED` are 2-bit fields from SPC700 register `$00F0` (CONTROL):
- `CLK_SPEED` = bits [7:6] — shifts base by 0-3 positions
- `TM_SPEED` = bits [5:4] — shifts 2x base by 0-3 positions

Default (both 0): `TM_STEP = 1 + 2 = 3`.

### Timer 0/1 (8 kHz base)
```vhdl
TM01_CNT[8:0] += TM_STEP each SPC700_CE_F
-- Overflow at bit pattern "11xxxxxxx" (≥ 384):
--   TM01_CNT masked to lower 7 bits, T0/T1 prescaler ticks
```

With default `TM_STEP = 3` and SPC700 at ~1.024 MHz: overflow occurs every ~128 SPC700 cycles → **~8 kHz** base rate for Timers 0 and 1.

Each timer then divides further by a programmable 8-bit divisor (`T0DIV`, `T1DIV`). The 4-bit output counter (`T0OUT`, `T1OUT`) increments on each divisor match.

### Timer 2 (64 kHz base)
```vhdl
TM2_CNT[5:0] += TM_STEP each SPC700_CE_F
-- Overflow at bit pattern "11xxxx" (≥ 48):
--   TM2_CNT masked to lower 4 bits, T2 prescaler ticks
```

With default `TM_STEP = 3`: overflow every ~16 SPC700 cycles → **~64 kHz** base rate. Divided further by `T2DIV`.

## 7. Coprocessor Clocking

All coprocessors receive `MCLK` (= `clk_sys`) as their clock input and `SYSCLKF_CE`/`SYSCLKR_CE` for synchronization with the main CPU bus. Each generates its own internal clock enable for its execution pipeline.

### GSU / SuperFX (`rtl/chip/GSU/GSU.vhd:463-487`)

```vhdl
CLK_CE <= not CLK_CE or SPEED or TURBO;
-- SPEED: GSU clock speed register bit
-- TURBO: external turbo switch
```

- Normal mode (`SPEED=0, TURBO=0`): `CLK_CE` toggles every MCLK → **10.74 MHz** effective rate
- Fast mode (`SPEED=1` or `TURBO=1`): `CLK_CE` stays high → **21.48 MHz** (every MCLK cycle)

The GSU execution enable is gated on falling edge of `CLK`:
```vhdl
EN <= ENABLE and FLAG_GO and CLK_CE;  -- sampled on falling_edge(CLK)
```

GSU cache RAM uses inverted `CLK` (`not CLK`) for its port 0, creating a half-cycle offset declared as asynchronous in `SNES.sdc`:
```tcl
create_generated_clock -name GSU_CACHE_CLK -source ... -invert ...
set_clock_groups -asynchronous -group [get_clocks { GSU_CACHE_CLK ... }]
```

During save states, `CLK_CE` is forced low via `SS_BUSY` to freeze the GSU.

### SA-1 (`rtl/chip/SA1/SA1.vhd:273-300`)

```vhdl
CLK_CE <= not CLK_CE;
if SYSCLKF_CE = '1' then
    CLK_CE <= '0';
```

`CLK_CE` toggles freely at ~10.74 MHz but is **phase-locked to the main CPU** by resetting to 0 on every `SYSCLKF_CE`. This means the SA-1 runs at 2x the SNES CPU rate but stays aligned to the main bus cycle boundaries.

The SA-1's internal 65C816 is clocked by:
```vhdl
P65_CE <= SA1_EN and CLK_CE;
```

The SA-1 tracks `SNES_SYSCLK` (a virtual clock level reconstructed from `SYSCLKF_CE`/`SYSCLKR_CE`) for bus arbitration — the SNES CPU and SA-1 CPU share ROM and BWRAM, and access windows are interleaved based on which half of the SNES system clock cycle it is.

### CX4 (`rtl/chip/CX4/CX4.vhd:490-510`)

The CX4 has no explicit clock divider. It receives an external `CE` enable from `main.v` and uses `SYSCLKF_CE`/`SYSCLKR_CE` directly for bus timing. Bus reads use a 2-cycle counter (`BUS_RD_CNT`) — when `BUSY=1`, a read strobe fires every 2 MCLK cycles (~10.74 MHz effective bus rate). When idle, reads are gated by `SYSCLKR_CE` or `SYSCLKF_CE` (main CPU rate).

CX4 data RAM uses inverted `CLK`, declared asynchronous in `SNES.sdc` similarly to the GSU cache.

## 8. SDRAM Controller (`rtl/sdram.sv`)

Runs entirely in the `clk_mem` domain (85.909 MHz):

```systemverilog
input clk,  // sdram is accessed at up to 128MHz
```

Timing parameters (at 85.9 MHz, ~11.6 ns period):
```
RASCAS_DELAY = 1 cycle  (tRCD=20ns → 1 cycle at 85MHz)
```

The SDRAM controller has two ports (`addr0/din0/dout0` and `addr1/din1/dout1`) for simultaneous CPU and DMA/download access.

### CDC: clk_sys → clk_mem

The SDRAM address/data/control signals originate in `clk_sys` but are consumed in `clk_mem`. The `SNES.sdc` constrains this crossing:

```tcl
set_max_delay 20 -from [get_registers { emu|hps_io|* emu|main|* ... }]
                 -to   [get_registers { emu|sdram|* }]

set_max_delay 23 -from [get_registers { emu|sdram|* }]
                 -to   [get_registers { emu|main|* emu|bsram|* emu|vram*|* }]
```

These are **max-delay constraints** (not false paths), meaning timing analysis ensures data crosses within the specified window. The 4:1 frequency ratio (85.9 / 21.5) provides natural multi-cycle margin.

Download data is explicitly synchronized:
```systemverilog
always @(posedge clk_mem) begin          // SNES.sv:861
    sdram_download_addr <= addr_download; // re-register in clk_mem domain
    sdram_download_data <= ioctl_dout;
    sdram_download_wr <= ioctl_wr;
end
```

### DDR3 Interface

`DDRAM_CLK` is directly assigned to `clk_mem` (`SNES.sv:1463`). Used for save states and MSU-1 data streaming. The `ddram` module handles burst transactions and is clocked from `clk_sys`, with the DDR clock output on `clk_mem`.

## 9. Clock Domain Summary

```
CLK_50M (50 MHz)
├── PLL reference input
└── pll_cfg management clock (PAL/NTSC reconfiguration)

clk_sys (21.477 MHz NTSC / 21.281 MHz PAL)
├── SNES core (MCLK)
│   ├── CPU.vhd → generates SYSCLKF_CE / SYSCLKR_CE
│   │   ├── 65C816 core (CE = INT_CLKF_CE, ~1.79-5.37 MHz variable)
│   │   ├── DMA engine (8 MCLK cycles per beat, ~2.68 MHz)
│   │   ├── CLK4_CE_F/R (~5.37 MHz fixed from DMA counter)
│   │   └── CLK8_CE_F (~2.68 MHz fixed from DMA counter)
│   ├── PPU.vhd → generates DOT_CLK / DOT_CLKF_CE / DOT_CLKR_CE
│   │   └── Dot clock: MCLK/4 = 5.37 MHz (with 2 dots/line at MCLK/6)
│   │       └── H_CNT: 0-339 per line, V_CNT: 0-261 (NTSC) / 0-311 (PAL)
│   ├── WRAM (SYSCLKF_CE gated)
│   └── Coprocessors (all receive MCLK + SYSCLKF/R_CE)
│       ├── GSU: CLK_CE toggles → 10.74 MHz (normal) / 21.48 MHz (turbo)
│       ├── SA1: CLK_CE toggles, phase-locked to SYSCLKF_CE → ~10.74 MHz
│       └── CX4: BUS_RD_CNT 2-cycle → ~10.74 MHz bus rate
├── Audio subsystem (DSPCLK = same clk_sys)
│   ├── DSP.vhd → CEGen produces CE at ~4.096 MHz
│   │   ├── Substep: ~4.096 MHz (1 per CE pulse)
│   │   ├── Step: ~1.024 MHz (1 per 4 substeps)
│   │   └── Sample: ~32 kHz (1 per 32 steps)
│   └── SMP.vhd → SPC700 at ~1.024 MHz (SPC700_CE_F = once per DSP step)
│       ├── Timer 0/1: ~8 kHz base ÷ T0DIV/T1DIV
│       └── Timer 2: ~64 kHz base ÷ T2DIV
├── Save state logic
├── I/O ports, light gun, cheat engine
└── ROM mirroring, backup RAM management

clk_mem (85.909 MHz)
├── SDRAM controller (sdram.sv)
├── DDRAM_CLK output
└── Download data synchronizer

CLK_VIDEO (42.955 MHz)
├── CE_PIXEL generation (÷8 normal = 5.37 MHz, ÷4 hires = 10.74 MHz)
├── Video mixer
├── Aspect ratio / crop logic
└── Sync signal re-timing

CLK_AUDIO (24.576 MHz, external)
└── audio_out I2S serializer
```
